## Исправление выборки и ручное удаление · 2026-10-04

Подтверждена ошибка прежнего OR-фильтра: ACCOMPLICE регистрирует INNER JOIN,
который исключает задачи исполнителя без соисполнителей. Выборка заменена на
DOER с прежней нижней границей ACTIVITY_DATE и без верхней. DOER проверен по
локальному ядру и прямым REST-запросом; в официальной таблице фильтров он пока
не документирован. Автоматической смены версии REST нет.

На настроенном тестовом портале независимо получены четыре задачи-кандидата:
одна без времени, две с ролью исполнителя (1800 и 3600 секунд), одна с ролью
соисполнителя (5400 секунд). Новый отчёт за 01–30.10.2026 завершён: 4/4,
три строки, 10800 секунд, без ошибок. Это проверка тестового портала из .env,
а не отдельная приёмка в облаке. Старые завершённые отчёты не пересчитывались.

Удаление проверено через HTTP: авторизация, CSRF, занятый advisory lock,
каскад строк/ошибок и сохранение соседнего отчёта. Playwright проверяет
отказ без исчезновения строки и последующее AJAX-удаление без навигации
на desktop/mobile. Vite base приведён к /build/ для загрузки CSS/chunks.
Документация жизненного цикла обновлена точечно.

Полная проверка: PHPUnit 52 теста / 232 assertions, Playwright 32 проверки,
JS unit 4 теста, production build, PHPStan level 5, container/Twig lint —
успешно. Prod-кеш Symfony обновлён. README — 177 строк. Миграций нет.
Scoped Symfony/security review: подтверждённых Critical/Important находок нет.

## Ревью

Применены `symfony-code-review`, правила безопасности проекта и независимое
read-only ревью по `requesting-code-review`. Три важных находки воспроизведены
падающими тестами и исправлены:

1. `.env` не должен перекрывать реальные переменные окружения процесса.
2. HTML/пустые HTTP 503/429 должны оставаться временными ошибками; некорректный
   JSON при успешном HTTP 200 остаётся фатальной ошибкой.
3. Некорректные идентификаторы и даты записей времени нельзя незаметно исключать
   до проверки пользователя и периода.

Добавлены проверка абсолютных дат со смещением, защита от повторяющейся страницы,
обработка исчерпания повторов команды, даты сбора и предупреждение о доступности
данных в интерфейсе, ссылки задач и дополнительные колонки CSV.

## Неточности документов и ограничения

В STYLE уточнено противоречие: ORM необязателен, поэтому entities требуются лишь
при выборе ORM; параметризованные DBAL-репозитории допустимы. В QUALITY_TOOLING
актуализирован статус установленных PHPUnit и PHPStan. Проектный лимит README
и необязательность docstring отражены в правилах документации и rules-check.

MCP Битрикс24 иногда объединяет контракты классического REST и REST 3.0 и
возвращает статью, не соответствующую названию. Исправление процесса: сверять
версию, заголовок и URL с официальной страницей, а не строить запросы из смеси.
Изменять внешний MCP-сервер проект не может.

Приёмка на рабочем портале **не выполнена**: требуется проверить настройку вебхука
через окружение приложения и сверить несколько задач с независимым расчётом, включая ручные записи прошлой
датой, таймер, разные роли и несколько страниц времени. Секреты для этого
не передавать в чат. Недоступные/удалённые задачи вебхук не восстановит.

Изменения оставлены в текущей рабочей копии `master`; коммит, push и изменение
пользовательского индекса вне явно запрошенного исключения init.md не выполнялись.

Независимое ревью выявило две Important ошибки, обе воспроизведены RED и исправлены:

1. OPERATION_TIME_LIMIT не расходует обычный бюджет даже перед последующим 503.
2. Повтор участников использует уже известное время и разрешает ошибку только
   после успешного получения роли; пустой повторный ответ времени не может
   ошибочно превратить сохранённую неизвестную роль в «полный» отчёт.

Scoped re-review: обе находки закрыты, новых Critical/Important нет.
Полная приёмка реального отчёта с независимой сверкой времени остаётся отдельной
операцией. REST 3.0 для соисполнителей/наблюдателей на проблемной задаче возвращал
500; ошибка сохраняется явно. Для исполнителя используется known responsibleId
из списка, что исключает ненужный запрос участников.

Rules check нового кода: нарушений обязательных правил не найдено. Короткие
одноразовые методы ReportRepository::nextRetryAt/taskRow/hasUnresolvedErrors —
обоснованные SQL-границы репозитория; Command::configure — контракт Symfony.
CSV::write — повторное использование защиты ячеек, Processor::advance — общий
атомарный переход для успеха/ошибки задачи. Нет обязательных docstring.
Подробная AS IS документация: [жизненный цикл](report-lifecycle.md).
