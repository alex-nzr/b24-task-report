# Оптимизированная выборка и быстрый запуск

Схема подтверждена пользователем в чате 02.10.2026. PHP 8.3, PostgreSQL 15, Symfony и официальный UI Kit остаются обязательными.

Для новых отчётов классический tasks.task.list выбирает текущих исполнителей или соисполнителей с ACTIVITY_DATE >= начало периода. Верхней границы активности нет. Это исключение из REST 3.0: его TaskDto разрешает фильтрацию только по id. Время фильтруется отдельно по сотруднику и периоду. Задача, из которой сотрудника уже исключили, не входит в новую выборку. Роли определяются по данным списка, без дополнительного REST-вызова для каждой задачи.

Курсор ID и верхний ID ограничивают обход. total_tasks хранит исходный total выбранных задач; это не атомарный снимок портала. Ранее сохранённые отчёты не удаляются. Незавершённые старые выборки безопасно перезапускаются без смешения результатов разных алгоритмов.

Форма имеет необязательный флаг collectNow. Только после CSRF, проверки сотрудника и дат создаётся отчёт и вызывается тот же конечный сборщик для этого ID. Сборщик и cron используют общую блокировку PostgreSQL. Если занято, новый отчёт остаётся в очереди. Бюджет по умолчанию 45 секунд мягкий: текущий шаг завершается, следующий не начинается. Бесконечного worker, shell-запуска и автоматической перезагрузки нет.

Записи показываются в часовом поясе отчёта как d.m.Y H:i:s. Длительность — накопленные часы:минуты, без ограничения 24 часами; исходные секунды сохраняются. Компактная версия содержит HTTPS-ссылки на задачи сотрудника, дробные часы и итог, копируется через буфер; неполные результаты явно помечаются.

Миграция добавляет total_tasks и удаляет неиспользуемую messenger_messages. Настройки приложения берутся только из окружения и обычных dotenv-файлов. Локальные профили доступа агента не являются источником настроек приложения. init.md остаётся локально, но не отслеживается Git.
