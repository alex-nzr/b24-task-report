# Интерфейс Битрикс24

Официальный пакет `@bitrix24/b24ui-nuxt` 2.14.0 работает с Vue и Vite;
Nuxt-сервер не используется. Выбор UI Kit закреплён в AGENTS.md и STYLE.md.

## Границы ответственности

Symfony продолжает проверять доступ, CSRF, сотрудников и период, создавать
задания и выгружать CSV. Контракт POST-форм не менялся: `_username`, `_password`,
`_csrf_token` для входа; `report_request[employeeId/from/to/collectNow/_token]` для отчёта;
`_token` для пересбора и `_csrf_token` для выхода.

Vue отвечает только за представление. `templates/base.html.twig` содержит
`#app` с серверным HTML и `script#app-data` с JSON. JSON_HEX_TAG/AMP/APOS/QUOT
защищают границу script; во Vue текст выводится интерполяцией, без v-html.
В payload перечислены только поля экрана; очередь pending_tasks, настройки
окружения, токен вебхука, хеш пароля и DB-доступы не передаются.
CSRF-токены в HTML являются частью обычного безопасного браузерного контракта.

`assets/main.js` монтирует `App.vue`, обёрнутый в B24App с русской локалью.
Страницы загружаются отдельными chunks.
Vue монтируется только после успешной загрузки компонента выбранной страницы;
при ошибке chunk серверная форма остаётся доступной (проверяется в браузере).
Плагин UI Kit настроен `router: false`: ссылки — обычные anchors, формы —
обычные POST, маршруты принадлежат Symfony.
Автообновление выполняет Vue через защищённый GET `/reports/{id}/progress`:
каждые пять секунд, без перезагрузки, с остановкой на терминальном статусе.
Endpoint читает только PostgreSQL; сбор выполняет конечный runner из Command
или после валидной формы с галочкой «Сформировать сразу». Общая блокировка
исключает параллельные сборщики; HTTP-запуск обрабатывает только новый отчёт.
Известные строки, промежуточная сумма и ошибки доступны при любом статусе.
Подробности хранения/сбора/CSV: [жизненный цикл](report-lifecycle.md).

Без JavaScript или до сборки доступны исходные HTML-формы и отчёт. Если сборки
нет, `ViteExtension::entry()` не добавляет несуществующие JS/CSS. Сборка всё равно
обязательна для рабочего оформления UI Kit; fallback не имитирует его дизайн.

## Компоненты и дизайн

- B24App/B24Container: общая оболочка и адаптивные границы.
- B24Card, B24FormField, B24Input и B24Select: вход и параметры отчёта.
- B24Button: действия и скачивание CSV.
- B24Checkbox: немедленный ограниченный запуск после проверки формы.
- B24Modal: компактный текст отчёта и кнопка копирования.
- B24Alert: серверные ошибки и состояние фонового сбора.
- B24Badge: понятные текстовые статусы и роли.
- B24TableWrapper: оформление семантических таблиц и прокрутка широкого отчёта.

Цвета, типографика, интервалы и оформление берутся из штатных токенов библиотеки.
Небольшой `assets/main.css` задаёт фон/шрифт через токены и видимый focus.
Заголовки используют `text-h1`/`text-h4`; пояснения — `--ui-color-base-2`.
`text-muted` и `text-description` оказались недостаточно контрастными для мелкого
текста на выбранном фоне (1.56 и 3.34 вместо минимум 4.5); это не меняется
подменой палитры, выбран подходящий существующий токен. Есть браузерный regression.

## Сборка и проверки

`npm ci` → `npm run build` создаёт `public/build/.vite/manifest.json` и
хешированные assets. `src/Twig/ViteExtension.php` читает manifest, поэтому Twig
не знает имён конкретных chunks. `npm run dev` — build watch, не SPA dev-server.
Весь `public/build` является результатом сборки и исключён из Git; при поставке
нужно передавать его целиком. Для hashed assets допустим длительный cache,
но HTML и manifest не должны оставаться устаревшими после обновления.

Vite использует `envDir: false` и `publicDir: false`: не загружает серверные
dotenv-файлы и не копирует PHP entrypoint в каталог frontend-сборки.
Исходный `.env` не изменялся в рамках UI-работы. Секреты загружает только backend.

Для проверки сначала `npm run build`, затем PHP-тесты контроллеров. Они создают
синтетические страницы login/index/report/invalid в `.ai/.tmp/ui-fixtures`.
`npx playwright install chromium` устанавливает тестовый браузер;
`npm run test:ui` поднимает тестовый статический сервер только на localhost.
На рабочих пользователях/задачах браузерные тесты не выполняются.

Тесты проверяют реальные компоненты UI Kit на ширинах 1440 и 390: вход, имена
полей и фактический POST, CSRF, доступность исправления неверного периода,
экранирование названия/комментариев, роль, сумму, CSV, детали и отсутствие
горизонтального переполнения всей страницы. Отдельно проверяется контраст текста.
Текущий набор содержит 24 проверки: также проверены даты `d.m.Y H:i:s`,
длительность в накопленных часах `HH:mm`, исходное количество задач, галочка,
flash-сообщения и компактный отчёт. При отказе clipboard текст выделяется
для ручного копирования; неполный отчёт содержит предупреждение в самом тексте.
Снимки экрана сохраняются в `.ai/.tmp/ui-*-desktop.png` / `ui-*-mobile.png`.

не из неэкспортируемого подкаталога `locale/ru`.
