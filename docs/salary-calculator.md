# Калькулятор зарплаты

На странице отчёта Vue пересчитывает окладную часть, наработку, премию и
выплату по премии (премия / 0,94) при изменении полей. Введённые суммы и расчёты
не отправляются на сервер, не сохраняются в БД, cookies или localStorage:
при перезагрузке страницы они сбрасываются. CSV остаётся отчётом времени.
Расчёт добавляется в «Компактную версию», когда все поля заполнены корректно.

## Календарная норма

Защищённый GET `/reports/{id}/workdays` читает период сохранённого отчёта.
`WorkingDays` через `BitrixClient::calendarSettings()` получает
`calendar.settings.get`: `week_holidays`, `year_holidays`, `year_workdays`.
Считает весь месяц, даже если отчёт охватывает только часть месяца.
Дополнительная рабочая дата имеет приоритет над выходным/праздником.
Это настройки календаря портала, не персональный график сотрудника и не
гарантированный официальный производственный календарь с актуальными переносами.
Вебхуку требуется доступ к календарю; секреты в браузер не передаются.

Ключ `working_days_YYYY-MM` в существующем `cache.bitrix` хранит норму сутки.
Ошибки REST/некорректные данные дают 21 с предупреждением, кешируются пять минут.
Для нескольких месяцев REST не вызывается: 21 и ручная норма с предупреждением;
автоматического распределения месячного оклада нет. Смена портала требует
очистить кеш приложения. Правки нормы в браузере не изменяют серверный кеш.

Фактические дни сначала равны норме. При изменении нормы синхронизируются,
пока пользователь сам не изменит фактические дни. Поздний ответ календаря
не перезаписывает уже отредактированную норму.

## Расчёт и ограничения

Часы берутся из суммы исходных секунд / 3600, без округления к шагу 0,5;
поле только для чтения. Часы отображаются до четырёх знаков после запятой,
но наработка считается по исходным секундам. При обновлении прогресса часы и расчёт обновляются,
но ручные значения сохраняются до ухода со страницы. При неполном отчёте
расчёт предварительный; предупреждение остаётся и в копируемом тексте.

`assets/salary.js` вычисляет оклад / норму × фактические дни, часы × ставку,
разность наработки и окладной части, затем премию / 0,94. Каждый денежный
этап округляется до целых рублей, как в примере требований. Нулевая норма,
пустые/отрицательные/нечисловые поля и небезопасно большие суммы блокируют расчёт.
Отрицательная премия сохраняется как разность, но выплата по ней равна нулю
на странице и в компактном тексте; показывается пояснение. Деление на 0,94
заменяет прежнее умножение на 1,06; остальные этапы и округление не изменены.

Без JavaScript исходный отчёт доступен, калькулятор недоступен с пояснением.
Тесты арифметики: `npm run test:unit`; UI: `npm run test:ui`;
календарь, кеш, fallback и доступ к endpoint проверяются PHPUnit.

В документации/MCP `year_workdays` отсутствует в таблице возвращаемых полей,
но присутствует в примере ответа. Реализация учитывает поле, отсутствие
трактует как отсутствие дополнительных рабочих дат.
